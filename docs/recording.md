# 104 主控按需录像

在主控 SSH 终端运行 `uav-record`，选择开始、单路停止、全部停止或状态。开始时支持编号多选，例如 `1,3,4`；`all` 选择当前方案的全部视频。退出菜单、关闭 SSH 后录像继续；用停止命令结束。开机默认不录像。

```bash
uav-record                       # 交互菜单
uav-record start 1 3 4           # 下视、前视算法、前视预览
uav-record start all             # 当前方案全部；可以随后追加其他路
uav-record status               # 实际写入帧数/等待重连/保存目录
uav-record stop 3                # 只停止前视算法
uav-record stop all              # 停止全部并关闭文件
```

编号在三种方案之间保持一致；不能开始录制当前方案未启用的流。

| 编号 | 名称 | 主控本地录像源 | 保存子目录 |
|---|---|---|---|
| 1 | 下视 MIPI | `rtsp://127.0.0.1:8554/board` | `board` |
| 2 | D455 彩色 | `rtsp://127.0.0.1:8554/rgb` | `rgb` |
| 3 | 前视算法 | `rtsp://127.0.0.1:8554/algorithm` | `algorithm` |
| 4 | 前视预览 | `rtsp://127.0.0.1:8554/preview` | `preview` |
| 5 | 算法板 Mino17 红外 | `rtsp://127.0.0.1:8554/infrared` | `infrared` |
| 6 | 云台可见光 | `rtsp://127.0.0.1:8555/gimbal` | `gimbal` |
| 7 | 云台红外 | `rtsp://127.0.0.1:8556/gimbal_ir` | `gimbal_ir` |

文件默认在主控 SSD：

```text
/data/uav-recordings/日期/日期_时间_任务编号/
  session.json
  board/连接时间_连接编号_00000.mkv
  board/连接时间_连接编号.csv
  board/status.json
  algorithm/...
```

默认约每 5 分钟保存一个 MKV，按原视频关键帧切分，因此长度可能略有差异。重连创建新文件。`session.json` 保存选择、源地址和开始/停止事件；各路 CSV 记录分段。录像是当前 RTSP 的压缩画面：前视算法流包含程序实际绘制的结果，下视 `/board` 是原始预览；D455 仅保存彩色视频，不含深度图和 IMU。

用 VLC 等支持 H.264/MKV 的播放器播放。需要 MP4 时可在电脑上转换容器，不必重新编码：

```bash
ffmpeg -i 输入.mkv -c copy 输出.mp4
```

## 安装及运行方式

v1.3.0 新增配套地面站“板端录像”面板，开机启动 `uav-record-api.service`（9072），录像本身仍默认关闭。已有主控在完整包内执行 `sudo python3 install_record_api.py`；104 已安装。新主控完整安装也包含接口。

地面站首次输入主控 IP 和 `sudo cat /etc/uav-record-api/token` 显示的本板连接码；MK22 `.36`，Wi-Fi `.104`。各板独立码，不公开发布。面板可多选、开始/追加、停止所选/全部，查询实际状态及路径；关闭地面站不停止录像。完整操作见 [地面站说明](https://github.com/Zhanghaohao666/uav-ground-station/blob/v1.01.09-board-recording/project-docs/BOARD_RECORDING.md)。

v1.2.0 完整主控安装器已包含录像命令及 systemd 模板。算法板角色不安装本录像工具。现有已安装 uav-switch 的主控可复制完整包后单独执行：

```bash
sudo python3 install_recorder.py
```

此增量安装不更改配置、不重启采集/转发、不启用开机录像；已有相同文件跳过，不同内容拒绝覆盖。`uav-record@.service` 是静态模板，各实例只由手动选择启动。每路独立 FFmpeg 进程直接复制压缩视频，断流独立重试；停止一路只关闭这一路。主控模式切换后，已录的公共流继续，停用的载荷流等待输入；用户需要用 `stop` 明确结束不用的录像。

启动前要求 `/data` 确实挂载。保留 10 GiB 可用空间，低于此值停止，不自动删历史文件，也不退回系统盘保存。正常停止会关闭当前文件；突然断电或强制终止可能损坏最后一个分段，已经关闭的分段保留。板卡重启后需重新手动选择录像。

## 带宽、空间与实测

从 `127.0.0.1` 录像不会增加 MK22 空中链路的流量，不依赖地面站是否拉流。视频需先到达主控，板间原有推送及云台取流仍会运行；录像不另向算法板或云台开启一个远端拉流连接。FFmpeg 使用 `-c:v copy`，省去解码和重新编码，但会增加本机 RTSP 封装、内存复制和磁盘写入。

按当前配置标称码率估算，十进制 GB/小时约为 `Mbps × 0.45`，实际随画面和码率控制变化：

| 视频 | 标称 Mbps | 约 GB/小时 |
|---|---:|---:|
| 下视 | 3 | 1.35 |
| D455 彩色 | 2 | 0.90 |
| 前视算法 | 5 | 2.25 |
| 前视预览 | 3 | 1.35 |
| 算法板红外 | 1.5 | 0.68 |
| 云台可见光 | 4.096 | 1.84 |
| 云台红外 | 1.5 | 0.68 |
| 七路合计 | 20.096 | 9.04 |

2026-10-08 在 104 的 RK3588/8 核、Ubuntu 22.04、512 GB SATA SSD 上进行约 35 秒短时验收，使用 5 秒分段验证切分：

- 六路有输入的视频同时生成文件，首末分段 ffprobe 均识别为 H.264，各路首段实际解码 10 帧成功。
- 算法板红外当时没有输入，独立等待重连，其余六路保持写入。
- 单独停止前视预览，其余录像继续；最终全部停止，原采集/转发进程 PID 保持不变。
- 第 30 秒录像进程 RSS 合计约 372 MiB，`ps %cpu` 合计 27.5%，约 0.28 个 CPU 核心。此值是进程生命周期平均，含正在重连的缺流一路；RSS 加总可能重复计入共享页。
- 这是短时功能和资源验收，未覆盖数小时写盘或录像期间断电；前视源时间戳存在间隔波动，录像保留原流时序。

v1.3.0 另通过生产 Qt 控制器在 104 测试新 API：两路写帧、缺席红外独立等待、只停止预览后下视继续，最终本次各路停止。接口处于 enabled/active，原视频 PID 不变；63 项 Python 测试通过。

摄像头视频与雷达原始点云可以分别保存，但本工具没有提供硬件同步时间戳。若用于严格的跨传感器对齐，需要后续配置时钟同步并保存传感器原始时间戳，不能只凭视频文件名对齐。
