# v1.7.1 RGA 应用修复与验证

日期：2026-11-06。适用现场 RK3588 BSP：Linux 5.10.226、RGA multicore v1.3.4、librga API 1.10.1_[4]。

## 已定位的触发链

两次失联前的内核记录均包含 RGA2 core[4] 拒绝超过 4GiB 物理地址的缓冲、任务提交失败，随后出现 bad rss/page table、负引用计数或内核异常。其中一次与前视原始预览低清分支 1920×1080→640×360 的普通虚拟地址提交同时发生。

这与 Rockchip 官方记录的错误路径 mm 引用重复释放修复相符，但尚未用厂商这份 BSP 的完整源码证明具体缺失哪个补丁：

- [Rockchip RGA FAQ：物理地址范围限制](https://github.com/airockchip/librga/blob/main/docs/Rockchip_FAQ_RGA_CN.md)
- [内核提交：avoid multiple drop current->mm](https://github.com/rockchip-linux/kernel/commit/402e40ea28051e642224e93768cfe83fd4f2b6ab)

第一轮改用合法 DMA32 导入缓冲后，并发测试还捕捉到 RGA2 硬件超时。此时低清保护已停掉本分支、高清继续出图，没有再造成内核内存异常。因此最终版进一步明确指定 RGA3 双核，不再自动调度至 RGA2。

## 实现与保留项

- 高清颜色转换、旋转与低清缩放统一使用受限 DMA32 heap、导入句柄和同步 CPU 缓存；内部 stride 按 16 对齐，外部可见分辨率及 NV12 UV 偏移正确。
- 线程独立、缓存槽位上限为 8；无订阅和线程退出释放句柄、映射与文件描述符。失败后停止该线程提交，无 RGA2/普通指针回退，低清失败只关闭本分支。
- `tracker_worker` SHA256 保持 `8d26f6b86c8f067c1e5f8571c7834828c6d080adfe128f7036c1ed1ab1856daa`；现场静态库、全部模型、画框衔接及两路旋转 0° 均未修改。算法帧和控制协议不变。
- 主控共用程序同步修复；RK3576 云台业务程序保持 v1.7.0 不变。

## 检查结果

- 202 项回归通过；11 个资源/失败场景通过 ASAN、UBSAN 和泄漏检查，包括申请/导入/同步/提交失败、禁止 RGA2 回退、线程退出、反复释放、缓存有界及图像越界保护。
- 同版 RK3588 合成图像测试：1080P 颜色转换、90/180/270° 旋转、NV12 Y/UV 最后行与缓冲尾部保护通过；240 次缩放、8 次创建/释放周期无 FD 遗留，平均缩放约 3.36ms。
- 算法板六路实际解码：前视两路高清 1920×1080、红外 640×512，低清分别为 640×360、640×360、320×256，每路连续解码 90 帧通过。
- 主控下视 `/board`、D455i `/rgb` 及各自 `_low` 每路连续解码 90 帧通过；地址保持不变。
- 主控本地同时接收算法板三路高清、三路低清 600 秒，全部正常结束。帧数：算法 17883、预览 17997、红外 14396；三路低清分别 9007、9006、9005。接收约为 30/30/24fps，低清约 15fps；无新增 RGA 提交/内核内存异常，三个服务重启计数均为 0。
- 五路低清（含主控下视和 D455i）并行打开后关闭，重复 3 轮，每路每轮解码 60 帧。每轮退出后等待租约过期，算法板 IR/算法/预览/worker 的 FD 数恢复为 28/33/28/16，PID 不变，没有资源递增。
- 修复版软重启实测通过：启动 ID 已改变，三路服务自动启动、重启计数 0；重新解码六路各 90 帧成功。内核仅保留外部 Wi-Fi 模块原有 taint 4096，没有新增内存/Oops/警告位；检测回调继续返回目标。

## 验证边界

不替换厂家内核、不修复该内核的所有潜在缺陷。短时真机测试和有限次数开关不能代替整夜运行、真实跟踪场景和外场无线链路验收。六路持续测试在主控本地接收，避免实验室 Wi-Fi 容量影响源端判断，不代表 MK22 可以同时传输六路高清。

主控本次启动早先还记录过一次 `eth0 NETDEV WATCHDOG` 警告，发生于修复部署之前；本次未改网卡驱动，也没有把已有警告当作修复程序产生的新内存异常。

已有设备应先备份并停对应采集服务，再原子替换已验证二进制；新板安装器拒绝强制覆盖未知旧部署。原程序保留供核对，但恢复已知问题版本须明确安排维护，不能自动重新启用故障路径。
